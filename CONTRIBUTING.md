# Contributing to azionapi-javascript-sdk

## Generated code

Every package directory (`credentials/`, `domains/`, ... `waf/`) is generated by
OpenAPI Generator from the Azion API specification. Do not edit generated files by hand:
change the specification or the generator configuration and regenerate, otherwise the
next generation overwrites the change. Repository-level files (`.github/`, `tests/`,
governance documents) are maintained by hand.

## Local checks

```bash
cd tests/vitest && npm ci && npm test                   # functional tests
shellcheck --severity=error */git_push.sh               # shell lint
```

## Pull requests

1. Branch from `main`.
2. Make the change (regenerated packages or repository-level files).
3. Run the local checks above.
4. Open a PR to `main`. CI runs compliance, security, code quality, tests and OSSF Scorecard.

## Commit and PR titles

We follow [Conventional Commits](https://www.conventionalcommits.org/). PR titles are
checked in CI and may carry a Jira key prefix:

```
<type>[(scope)]: <description>
[ENG-123] feat(domains): regenerate from the v4 specification
[NO-ISSUE] chore: update CODEOWNERS
```

Types: `feat`, `fix`, `docs`, `chore`, `ci`, `test`, `refactor`, `perf`, `build`, `revert`.

## Versioning

Every push to `main` creates the next `vX.Y.Z` tag (minor bump by default). Add `#major`,
`#patch` or `#none` to a commit message to change the bump.

## Security

Do not open public issues for vulnerabilities; follow [SECURITY.md](SECURITY.md).
